اگر `git clone` در شبکهٔ شما کند یا مسدود بود، نصب‌کننده خودش به‌صورت خودکار همان نسخه را با یک درخواست HTTPS از `codeload.github.com` می‌گیرد. برای تغییر رفتار:

```bash
sudo RAAH_TARBALL_TIMEOUT=180 bash /tmp/raah-install.sh --menu   # مهلت بیشتر برای شبکهٔ کند
sudo RAAH_REF=main bash /tmp/raah-install.sh --menu              # نصب آخرین کد روی شاخهٔ main
```

**راه** لایهٔ انتقال بین دو سرور ایران و خارج/مقصد است. کاربران، UUID، رمز، تاریخ انقضا، سهمیه و پنل باید در `x-ui`/`3x-ui` بمانند؛ Raah نباید مالک کاربرهای نهایی باشد. مسیر QUIC برای ترافیک TCP/UDP و مسیر TCP/REALITY به‌عنوان جایگزین قرار می‌گیرد.

> این نسخهٔ اولیه است. هیچ پروتکلی تضمین نمی‌کند که شناسایی یا مسدود نشود. قطع برق، مسیر بین‌الملل، فیلتر ارائه‌دهنده یا خاموش‌شدن کامل سرور را هم نرم‌افزار نمی‌تواند جبران کند.

## در این نسخه

- تولید کانفیگ جدا برای سرور خارج/مقصد، ایران و کلاینت لینوکس در حالت مستقیم، ریورس یا هر دو.
- Hysteria 2 روی QUIC برای TCP و UDP، و VLESS/REALITY روی TCP به‌عنوان مسیر جایگزین.
- اسکن SNI برای REALITY و ساخت چند مسیر fallback؛ هر SNI روی پورت TCP جدا ساخته می‌شود و `urltest` خودش مسیر سالم‌تر را انتخاب می‌کند.
- انتخاب خودکار مسیر سالم خارج/مقصد و ورودی کم‌تأخیر ایران با آزمون URL؛ این نسخه ترافیک چند کاربر را هم‌زمان بین سرورها پخش نمی‌کند.
- امکان انتخاب پورت؛ هیچ پورتی را در UFW یا فایروال پنل VPS باز نمی‌کند. هنگام فعال‌بودن port hopping فقط جدول DNAT مجزای خود Raah را مدیریت می‌کند.
- کانفیگ مستقل زیر مسیر `/etc/raah`؛ فایل‌ها و سرویس x-ui دست‌کاری نمی‌شوند.
- ابزارهای عملیاتی برای تولید برنامهٔ UFW، چک سلامت نصب، چک سقف مصرف host/interface و گزارش متادیتای لاگ Xray/x-ui.
- نمایش مجموع حجم ورودی/خروجی کارت شبکه، load و memory، بررسی سلامت سرویس TCP با اعلان تلگرام، و probe ساده برای latency/jitter اتصال TCP.
- تست end-to-end با کانفیگ واقعی کلاینت از مسیر ایران، خارج و مقصد HTTP/HTTPS.

این طراحی یک VPN کامل لایهٔ ۳ نیست؛ TCP و UDP را از طریق پراکسی عبور می‌دهد، اما ICMP و همهٔ پروتکل‌های IP را منتقل نمی‌کند. برای استفاده، کلاینت سازگار با sing-box و پشتیبانی TUN لازم است.

## راه‌اندازی

این بخش کوتاه‌ترین مسیر از صفر تا تونل قابل‌استفاده است. شش مرحله را به‌ترتیب انجام بده. هرچه بعد از این آمده اختیاری است.

### قبل از شروع چه چیزی لازم داری

| چیز | چرا |
| --- | --- |
| **دو** سرور لینوکسی (VPS) | Raah ارتباط سرور به سرور است. روی یک ماشین اجرا نمی‌شود. |
| اوبونتو 22.04/24.04 روی هر دو، با دسترسی `root` | نصب‌کننده سرویس سیستمی می‌سازد. |
| یک دامنه **به‌همراه** گواهی TLS برای سرور خارج | Hysteria 2 به آن نیاز دارد. فقط IP کافی نیست. |
| حدود ۲۰ دقیقه | بیشترش انتظار برای دانلود است. |

اول نقش هر سرور را مشخص کن و اسم‌ها را قاطی نکن:

- **سرور خارج** — ترافیک تو را می‌گیرد و به اینترنت می‌فرستد. معمولاً یک VPS ارزان در کشور نزدیک.
- **سرور ایران** — نقطهٔ ورودی که کلاینت‌ها به آن وصل می‌شوند. IP این سرور همان چیزی است که دوستانت در کلاینت وارد می‌کنند.

### مرحلهٔ ۱ — ساخت bundle

این کار را **یک بار** و روی یکی از دو سرور انجام بده. یک جفت فایل هماهنگ می‌سازد که هر دو سرور باید داشته باشند تا با هم حرف بزنند.

```bash
curl -fsSL https://raw.githubusercontent.com/qasamij/raah-tunnel/main/one-click-install.sh -o /tmp/raah-install.sh
sudo bash /tmp/raah-install.sh --menu
```

گزینه‌ای را انتخاب کن که با ماشینی که همین الان رویش هستی بخواند:

| این ماشین | گزینه |
| --- | --- |
| **سرور ایران** | **۱** (IRAN server) |
| **سرور خارج** | **۲** (OUTSIDE server) |

بار اول هنوز bundleای وجود ندارد، و نصب‌کننده **قبل از ساختن** می‌پرسد — چون هر دو سرور باید کلیدهای یکسان داشته باشند. برای ادامه `generate` را تایپ کن. روی سرور دوم bundle از قبل هست، پس نصب‌کننده کلید تازه نمی‌سازد و همان را به کار می‌برد. در ویزارد:

- برای «Outside server PUBLIC IP» آی‌پی سرور **خارج** را بده.
- برای «Iran server PUBLIC IP» آی‌پی سرور **ایران** را بده.
- اگر مقداری داخل `[کروشه]` پیشنهاد شد، Enter بزن تا همان قبول شود.
- اگر دامنهٔ گواهی TLS اشتباه به نظر رسید، خودت تایپ کن.

فایل‌ها در `/root/raah-private-bundle/` ساخته می‌شوند. دو فایلی که مهم‌اند:

- `outside.json` → برای **سرور خارج**
- `iran-01.json` → برای **سرور ایران**

### مرحلهٔ ۲ — گواهی TLS روی هر دو سرور

Hysteria 2 بدون گواهی معتبر بالا نمی‌آید، پس این تنها مرحله‌ای است که خودکار نمی‌شود. برای دامنهٔ خارج یک گواهی واقعی بگیر، بعد روی **هر دو** سرور این دو فایل را بساز:

```
/etc/raah/tls/fullchain.pem
/etc/raah/tls/privkey.pem
```

اگر هنوز دامنه و گواهی نداری، همین‌جا متوقف شو و اول آن را تهیه کن. بدون آن هیچ‌چیز کار نمی‌کند.

### مرحلهٔ ۳ — نصب روی سرور خارج

ویزارد می‌پرسد آیا همین ماشین سهم سرور مقابل را بفرستد و نصبش را آنجا اجرا کند.
اگر `y` بدهی، کل کار انجام می‌شود:

```
  Shall this machine copy them over and install them there? [y/N] y
  OUTSIDE server PUBLIC IP [203.0.113.10]:
  SSH user on that server [root]:
  Directory to place the files in on that server [/root]:
  About to do this on root@203.0.113.10:
    ...
  Continue? [y/N] y
```

هر پیشوند مقداری را نشان می‌دهد که خودش قصد استفاده از آن را دارد، پس
**اینتر همان را قبول می‌کند**. پیش‌فرض‌ها از جواب‌هایی می‌آیند که در ویزارد
داده‌ای؛ در حالت معمول کل گفتگو می‌شود: `y`، اینتر، اینتر، اینتر، `y`.

کارهایی که به‌ترتیب انجام می‌شود:

۱. وجود یک کلید SSH قابل‌استفاده را بررسی می‌کند. اگر نبود، پیشنهاد می‌دهد یکی
   بسازد و نیمهٔ عمومی‌اش را چاپ می‌کند تا روی سرور مقابل اضافه کنی. هرگز رمز عبور
   نمی‌پرسد، ذخیره نمی‌کند و تایپ نمی‌کند.
۲. ورود را می‌آزماید و بررسی می‌کند که آیا آن سرور از قبل گواهی TLS دارد؛ اگر
   ندارد، قبل از هر کاری هشدار می‌دهد.
۳. دقیقاً نشان می‌دهد چه چیزی کجا می‌رود و منتظر `y` می‌ماند.
۴. کانفیگ **و** فایل `.install.json`‌اش را با یک `scp` می‌فرستد، به‌همراه خودِ
   اسکریپت نصب در `/tmp/raah-install.sh`.
۵. آنجا `sudo bash /tmp/raah-install.sh --config ... --start` را اجرا می‌کند و
   نتیجه را گزارش می‌دهد.

اگر در پیشوند اول `n` بدهی، یا هرجا `Ctrl-C` بزنی، هیچ چیزی فرستاده نمی‌شود و
به‌جایش دستورهای دستی چاپ می‌شوند:

```bash
scp /root/raah-private-bundle/outside.json /root/raah-private-bundle/outside.install.json root@OUTSIDE_IP:/root/
ssh root@OUTSIDE_IP
curl -fsSL https://raw.githubusercontent.com/qasamij/raah-tunnel/main/one-click-install.sh -o /tmp/raah-install.sh
sudo bash /tmp/raah-install.sh --config /root/outside.json --start
```

فایل `.install.json` اختیاری نیست: همین فایل است که پرش پورت Hysteria 2 را روی
این سرور فعال می‌کند. بدون آن، سرویس بالا می‌آید و `sing-box check` هم موفق
می‌شود، ولی بازهٔ پرش هرگز بازredirect نمی‌شود و تونل بی‌صدا به مسیر کندتر
می‌افتد.

### مرحلهٔ ۴ — نصب روی سرور ایران

همین پیشنهاد وقتی سرور ایران را راه‌اندازی می‌کنی هم ظاهر می‌شود، و آن‌وقت
`iran-01.json` را همراه `iran-01.install.json` به آدرس سرور خارج می‌فرستد. این
کار را فقط یک‌بار انجام می‌دهی، روی هر سروری که اول راه‌اندازی کرده‌ای.

### کدام نیمه روی این سرور می‌نشیند؟

هر bundle برای هر سرور یک کانفیگ دارد، و گذاشتن کانفیگ اشتباه سر جای درست،
آرام‌ترین اشتباه کل پروژه است: `sing-box` هر دو فایل را قبول می‌کند، سرویس بالا
می‌آید، تونل برقرار می‌شود، و فقط ترافیکی که انتظارش را داشتی عبور نمی‌کند — بدون
اینکه چیزی در لاگ توضیحش دهد.

برای همین، نصب‌کننده هر کانفیگ را می‌خواند و خودش تشخیص می‌دهد کدام نیمه است:

| نیمه | روی کدام سرور | چطور تشخیص داده می‌شود |
| --- | --- | --- |
| `outside.json` | سرور خارج (entry) | همهٔ outboundها فقط `direct`، `block` یا `dns` هستند |
| `iran-01.json` | سرور ایران (exit) | یک outbound دارد که به سمت همتا وصل می‌شود |
| `client-linux.json` | دستگاه خودت | inbound از نوع `tun` دارد |

این بررسی ساختار خودِ فایل را می‌خواند، پس کانفیگی که تغییر نام داده یا دستی
کپی شده باشد هم درست تشخیص داده می‌شود. اگر نتیجه با آنچه گفتی این سرور چیست
نخواند، هشداری می‌بینی که هر دو نیمه را نام می‌برد. **نصب باز هم انجام می‌شود.**
جابه‌جا کردن یک سرور کار مشروعی است و یک حدس نادرست نباید دلیل بالا نیامدن یک
سرور باشد.

### مرحلهٔ ۵ — باز کردن پورت‌ها

Raah هرگز فایروال تو را دست نمی‌زند. فایل `DEPLOY.txt` دقیقاً می‌گوید کدام پورت‌ها را باز کنی. روی **هر دو** سرور، این پورت‌ها را در **دو** جا باز کن:

۱. پنل ارائه‌دهندهٔ سرور (Hetzner، DigitalOcean، Contabo و…)
۲. خود `ufw` روی ماشین

برای دیدن فهرست یک کانفیگ:

```bash
python3 /opt/raah-tunnel/raahctl.py firewall-plan /root/raah-private-bundle/outside.json
```

مقادیر پیش‌فرض، اگر چیزی را عوض نکرده باشی: **UDP 8443** (هیستری ۲) و **TCP 7788** خارج / **TCP 8877** ایران (REALITY).

### مرحلهٔ ۶ — مطمئن شو کار می‌کند

روی هر سروری که بخواهی، منو نشان می‌دهد سرویس زنده است یا نه:

```bash
sudo raah-install --menu
```

- **گزینهٔ ۵** — وضعیت سرویس
- **گزینهٔ ۶** — تست end-to-end؛ به `client-linux.json` بده تا کل مسیر (سرور تو ← ایران ← خارج ← اینترنت) سنجیده شود. این همان تستی است که نشان می‌دهد تونل واقعاً ترافیک عبور می‌دهد.

بعد `client-linux.json` را از `/root/raah-private-bundle/` به دستگاهی که قرار است تونل را استفاده کند کپی کن. مخصوص کلاینت `sing-box` با پشتیبانی TUN است.

### اگر مشکلی پیش آمد

| مشکل | چه‌کار کن |
| --- | --- |
| `Could not download ... over git or HTTPS` | نصب‌کننده خودش آرشیو را هم امتحان کرده. اینترنت این سرور را بررسی کن. |
| سرویس بالا نمی‌آید | گزینهٔ ۵. معمول‌ترین علت، نبود گواهی TLS است. |
| سرویس‌ها بالا هستند ولی تست شکست می‌خورد | پورت‌ها باز نیستند، یا فایل کلاینت قدیمی است. |
| روی یک شبکه کار می‌کند ولی روی شبکهٔ تو نه | **TCP و UDP** را برای کل بازهٔ پورت باز کن. |

### IPv6

راه روی IPv6 کار می‌کند و این یک ویژگی آزموده‌شده است، نه یک فرض. تولیدکننده هرجا
نام میزبان می‌پذیرد، آدرس خام IPv6 هم می‌پذیرد؛ هر inbound سرور روی `::` گوش می‌دهد
(روی لینوکس dual-stack است، پس یک پورت هر دو خانواده را سرویس می‌دهد)؛ جدول
nftables مربوط به port hopping در خانوادهٔ `inet` است، پس یک مجموعه قاعده هر دو
خانواده را هدایت می‌کند؛ و کلاینت از قبل یک ULA دارد.

آنچه IPv6 **نمی‌دهد**، افزونگی بین دو خانوادهٔ آدرس است. هر گرهٔ ایران و سرور خارج
دقیقاً یک آدرس دارند و گروه‌های `urltest` بین گره‌ها انتخاب می‌کنند، نه بین خانواده‌های
آدرس. سروری که هم IPv4 دارد و هم IPv6، از هرکدام ثبت کرده باشی در دسترس است؛ دیگری
به‌عنوان backup استفاده نمی‌شود. برای failover بین خانواده‌ها باید همان سرور را با هر
دو آدرس چند بار در فهرست بیاوری، که تصمیم آگاهانهٔ خودت است نه رفتار خودکار.

نکته‌های عملی:

- آدرس خام را وارد کن: `2001:db8:122::10`، نه `[2001:db8:122::10]`. اگر براکت‌دار
  کپی کنی، ویزارد براکت را برمی‌دارد و باقیمانده را ذخیره می‌کند.
- آدرس خام IPv6 نمی‌تواند گواهی TLS هیستری ۲ را حمل کند. در حالت v6-only از نام
  دامنه برای گواهی استفاده کن، یا گواهی‌ای که IP SAN دارد.
- `ufw allow <port>/tcp` و `ufw allow <port>/udp` هر دو خانواده را پوشش می‌دهند، به
  شرط آنکه `IPV6=yes` در `/etc/default/ufw` باشد. فایروال پنل VPS جداست و باید IPv6
  را هم باز کند.
- در CI، `sing-box check` یک bundle فامیلی ۶ را کنار فامیلی ۴ اعتبارسنجی می‌کند و
  `tests/test_ipv6.py` ویژگی‌های بالا را تضمین می‌کند.

### نکته‌هایی که بهتر است بدانی

**شناسایی خودکار IP.** ویزارد به‌طور پیش‌فرض با HTTPS و به‌ترتیب از
`api4.ipify.org`، `ifconfig.me` و `icanhazip.com` تلاش می‌کند IP عمومی **همین
سرور** را پیدا کند و کشورش را با `ipwho.is` بپرسد. با اولین پاسخ معتبر، بقیهٔ
درخواست‌ها اجرا نمی‌شوند. این یعنی IP سرورت در اختیار آن سرویس‌ها قرار می‌گیرد.
پیش از قبول IP پیشنهادی، نقش همین سرور (`Iran` یا `Outside`) را با پنل VPS
تطبیق بده؛ اگر ویزارد از پشت پراکسی اجرا شود IP تشخیص‌داده‌شده می‌تواند اشتباه
باشد. برای صرف‌نظر از درخواست‌های آنلاین:

```bash
sudo bash /tmp/raah-install.sh --generate --no-discovery
```

**پوشهٔ نصب تغییریافته.** اگر `/opt/raah-tunnel` تغییر محلی داشته باشد، نصب‌کننده
آن را حذف یا بازنویسی نمی‌کند؛ فهرست فایل‌های تغییرکرده را نشان می‌دهد و عملیات
همان اجرا را از یک کپی تمیز موقت انجام می‌دهد.

**گواهی.** نصب‌کننده برایت دامنه یا گواهی صادر نمی‌کند. با صرف داشتن IP عمومی
نمی‌توان مرحلهٔ گواهی را درست تکمیل کرد.

**رابطه با x-ui.** نصب‌کننده وابستگی‌ها را می‌گیرد و سرویس مستقل
`raah-sing-box` می‌سازد. اما **Raah به‌تنهایی کاربران و inboundهای x-ui را به این
تونل وصل نمی‌کند**؛ مسیر خروجی پنل را جداگانه تنظیم کن.

### ویرایش امن bundle

از منوی نصب گزینهٔ `7` را انتخاب کن، یا مستقیم اجرا کن:

```bash
python3 raahctl.py edit-bundle /root/raah-private-bundle
```

می‌توانی IP/دامنهٔ خارج، IP/دامنهٔ هر سرور ایران، پورت‌های Hysteria 2 و REALITY، فهرست SNI و Health URL هر سمت، و بازهٔ failover را انتخاب و ویرایش کنی. ابزار پیش از تغییر، یک بکاپ زمان‌دار با مجوز `700/600` کنار bundle می‌سازد، کلیدها و UUIDها را نگه می‌دارد و همهٔ فایل‌های سرور و کلاینت را هماهنگ بازسازی می‌کند. بعد از تغییر، فایل JSON متناظر را دوباره روی هر سرور نصب و پروفایل کلاینت به‌روز را توزیع کن.

بازهٔ failover گزینهٔ `12` در همان منوی ویرایش است، و `--health-interval` همان کار را
بدون پرسش انجام می‌دهد:

```bash
python3 raahctl.py edit-bundle /root/raah-private-bundle --health-interval 45s
```

این گزینه مقدار `interval` را در همهٔ گروه‌های `urltest` همهٔ فایل‌های بازسازی‌شده
بازنویسی می‌کند، تا دو سرور با سرعت‌های متفاوت failover نکنند. مقدارها به شکل
مدت‌زمان Go نوشته می‌شوند (`ms`، `s`، `m`، `h`)؛ `0s` رد می‌شود، چون بازهٔ صفر
باعث می‌شود sing-box به‌جای failover مدام به Health URL بزند. حد پایینِ دیگری
لازم نیست، پس `10s` همچنان انتخاب معقولی است.

نمونهٔ غیرتعاملی برای تعویض سریع IP خارج:

```bash
python3 raahctl.py edit-bundle /root/raah-private-bundle \
  --outside-address NEW_OUTSIDE_IP
```

نمونهٔ تعویض IP سرور ایران اول:

```bash
python3 raahctl.py edit-bundle /root/raah-private-bundle \
  --iran-address 1=NEW_IRAN_IP
```

بعد از تغییر IP خارج، `outside.json` را روی سرور خارج جدید و `iran-01.json` را روی سرور ایران دوباره نصب کن. بعد از تغییر IP ایران، `iran-01.json` را روی همان سرور و `client-linux.json` را برای کلاینت‌ها به‌روز کن. ویرایشگر bundle سرویس‌های دو سرور را از راه دور restart نمی‌کند.

پس از اولین نصب، منو را با `sudo raah-install --menu` باز کن. گزینهٔ `8` آخرین تگ پایدار منتشرشده را نصب می‌کند. گزینهٔ `9` پس از نوشتن عبارت `UNINSTALL` سرویس و فایل‌های نصب Raah را حذف می‌کند؛ حذف bundle محرمانه یک تأیید جدا دارد. بستهٔ مشترک `sing-box` عمداً پاک نمی‌شود.

ویزارد ساده آدرس سرور خارج/مقصد، یک یا چند IP/دامنهٔ ورودی ایران، دامنه‌های گواهی TLS، SNI و پورت‌ها را می‌پرسد. در حالت مستقیم این فایل‌ها را می‌سازد:

برای پرسش‌های بیشتر مثل مسیر اختصاصی گواهی و SNI مجزای ایران، از `python3 raahctl.py generate --advanced --out ./private-bundle` استفاده کن. در حالت ساده مسیر گواهی هر دو سرور ثابت است و تعداد پرسش‌ها کمتر است.

- `outside.json`
- `outside.install.json` برای تنظیم امن DNAT و port hopping همان سرور
- `iran-01.json`، `iran-02.json` و ... (هر فایل مخصوص یک ورودی ایران است)
- `iran-01.install.json`، `iran-02.install.json` و ...
- `client-linux.json`
- `DEPLOY.txt`

در حالت ریورس، فایل‌های `reverse-outside-entry.json`، `reverse-iran-exit-01.json`، فایل‌های `.install.json` متناظر و `reverse-client-linux.json` ساخته می‌شوند. در حالت `both` دو پوشهٔ جدا به نام‌های `direct` و `reverse` ساخته می‌شود. هنگام انتقال، JSON هر سرور و فایل `.install.json` هم‌نام آن را کنار هم نگه دار.

فایل‌ها محرمانه‌اند و با مجوز محدود ساخته می‌شوند. آن‌ها را در GitHub قرار نده؛ از SSH/SCP برای انتقال استفاده کن و پس از نصب نسخهٔ خصوصی را پاک کن. سرویس راه روی پورت‌های خودش اجرا می‌شود و x-ui را تغییر نمی‌دهد.

برای نصب دستی نیز دستورها را **روی دو سرور جداگانه** اجرا کن. اسکریپت و کانفیگ مربوطه باید از قبل در همان سرور موجود باشد.

**سرور خارج:**

```bash
cd /opt/raah-tunnel
sudo bash scripts/install-unit.sh /root/raah-private-bundle/outside.json
sudo systemctl enable --now raah-sing-box
```

**سرور ایران:**

```bash
cd /opt/raah-tunnel
sudo bash scripts/install-unit.sh /root/raah-private-bundle/iran-01.json
sudo systemctl enable --now raah-sing-box
```

برای سرور ایران دوم از `iran-02.json` همان سرور استفاده کن. اگر بعداً کانفیگ را عوض کردی، `sudo systemctl restart raah-sing-box` را اجرا کن.

اسکریپت، کانفیگ را پیش از نصب اعتبارسنجی می‌کند؛ پورت فایروال را باز نمی‌کند و x-ui را ریستارت نمی‌کند. برای port hopping فقط جدول DNAT مجزای `raah_porthop` را می‌سازد؛ بازکردن کل بازهٔ UDP در UFW و فایروال پنل VPS با شماست.

پورت پایهٔ پیش‌فرض REALITY خارج/مقصد TCP/7788 و ایران TCP/8877 است تا دو سمت با هم قاطی نشوند. اگر چند SNI وارد کنی، پورت‌های بعدی خودکار مصرف می‌شوند؛ مثلا خارج/مقصد `7788, 7789, 7790` و ایران `8877, 8878, 8879`.

حالت پیشرفته Health URL جدا برای مسیر خارج و ایران و زمان‌بندی `urltest` را می‌پرسد. مقدار پیش‌فرض `https://cp.cloudflare.com/generate_204` است؛ اگر روی مسیر واقعی قابل دسترس نبود از گزینهٔ `7` منو آن را تغییر بده. برای failover سریع‌تر می‌توانی `10s` بدهی؛ مقدار آرام‌تر و پیش‌فرض `15s` است.

## نکته‌های عملی

- Hysteria 2 برای کار به UDP نیاز دارد. Salamander/Gecko یا جابه‌جایی پورت ممکن است در بعضی مسیرها کمک کند، اما UDP مسدودشده را تضمینی باز نمی‌کند.
- کلاینت sing-box 1.14 از DNS رمزگذاری‌شدهٔ DoH داخل مسیر انتخاب‌شده و حالت `dns_mode: hijack` استفاده می‌کند. قالب قدیمی FakeIP در 1.14 حذف شده و عمداً تولید نمی‌شود.
- port hopping هایستریا اکنون هماهنگ پیاده شده است: کلاینت `server_ports` و `hop_interval` می‌گیرد و فایل `.install.json` متناظر یک سرویس مستقل nftables برای DNAT می‌سازد. بازهٔ کامل UDP نوشته‌شده در `DEPLOY.txt` را همچنان باید در فایروال پنل VPS باز کنی.
- REALITY روی TCP مسیر جایگزین است؛ ارسال UDP از داخل پراکسی TCP ممکن است با تأخیر و jitter بیشتری همراه شود. برای بازی، مسیر UDP سالم کیفیت بهتری می‌دهد.
- SNI اسکن‌شده فقط از دید همان ماشین تست معتبر است. بهتر است `sni-scan` را از ایران و خارج/مقصد جداگانه اجرا کنی. در حالت چند SNI، اگر یکی از مسیرهای REALITY مشکل پیدا کند، sing-box با `urltest` مسیرهای دیگر را انتخاب می‌کند.
- نام دامنهٔ Hysteria باید گواهی منطبق داشته باشد. دامنه را در Arvan یا Cloudflare به‌صورت DNS-only تنظیم کن؛ CDN معمولی QUIC تونل را عبور نمی‌دهد.
- حالت direct یعنی کلاینت به ایران وصل می‌شود و خارج/مقصد خروجی اینترنت است. حالت reverse یعنی کلاینت به خارج/مقصد وصل می‌شود و یکی از سرورهای ایران خروجی می‌شود. اگر هر دو حالت را روی یک میزبان هم‌زمان می‌خواهی، پورت‌های یکی را تغییر بده تا تداخل نکنند.
- انتخاب ورودی این نسخه در سمت کلاینت است: sing-box ورودی‌های ایران را آزمایش می‌کند و یکی را برمی‌گزیند؛ این توزیع هم‌زمان بار بین چند سرور نیست. DNS فقط نام را به IP تبدیل می‌کند و اتصال جاری را هنگام قطعی حفظ نمی‌کند.
- مدیریت اصلی کاربر باید در x-ui/3x-ui انجام شود. دستورهای `add-user`، `revoke-user` و `enforce-users` فقط برای سازگاری با bundleهای قدیمی باقی مانده‌اند و نباید برای کاربران x-ui استفاده شوند.
- `audit-report` لاگ دسترسی Xray/x-ui را بر اساس کاربر، مقصد، پروتکل، زمان اتصال و حجم جمع‌بندی می‌کند. برای HTTPS معمولاً دامنه/SNI دیده می‌شود، نه مسیر کامل URL یا محتوای صفحه.
- `stats` و `quota-check` مجموع ترافیک کارت شبکه از زمان روشن‌شدن سرور را نشان می‌دهند؛ سهمیهٔ کاربر به کاربر هنوز enforce نمی‌شود.
- هشدار TCP را روی یک سرور مستقل اجرا کن تا خاموش‌شدن خود سرور مانیتورشونده را هم متوجه شود. ابزار داخلی فعلی UDP/Hysteria را به‌صورت end-to-end probe نمی‌کند و مانیتور داخل همان سرور نمی‌تواند قطعی برق یا اینترنت خودش را گزارش کند.

```bash
python3 raahctl.py stats --interface eth0
python3 raahctl.py quota-check --interface eth0 --limit-gb 500
python3 raahctl.py status --interface eth0
python3 raahctl.py doctor ./private-bundle
python3 raahctl.py audit-report /var/log/xray/access.log --user ali
python3 raahctl.py firewall-plan ./private-bundle --ssh-port 22
python3 raahctl.py probe --host ir-entry.example.net --port 8877 --count 20
python3 raahctl.py e2e-probe ./private-bundle/client-linux.json --count 5
python3 raahctl.py watch --host ir-entry.example.net --port 8877 --interval 30 --telegram-env
```

دستور `e2e-probe` یک ورودی SOCKS فقط روی `127.0.0.1` و در یک پوشهٔ موقت با مجوز محدود می‌سازد، کانفیگ را با `sing-box check` اعتبارسنجی می‌کند و درخواست HTTP/HTTPS را با `curl` از کل مسیر عبور می‌دهد. برای آزمایش یک مسیر مشخص، تگ آن را با `--outbound TAG` بده؛ بدون این گزینه همان `urltest` نهایی کانفیگ آزمایش می‌شود. این تست باید از دستگاه یا شبکه‌ای اجرا شود که نقش کلاینت واقعی را دارد.

برای اعلان، متغیرهای `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` را فقط روی ماشین مانیتور تنظیم کن.

### لاگ و حریم خصوصی

لاگ فعالیت باید در x-ui/Xray و با اطلاع کاربران فعال شود. فقط متادیتای لازم مانند زمان، کاربر، دامنه/مقصد، پروتکل و حجم را نگه‌دار؛ بدنهٔ ترافیک، رمزها و مسیر کامل HTTPS قابل ثبت امن نیستند. فایل لاگ را با دسترسی `600`، چرخش روزانه و نگهداری محدود (مثلاً ۷ یا ۳۰ روز) ذخیره کن. Raah این لاگ را تولید یا به تلگرام ارسال نمی‌کند.
